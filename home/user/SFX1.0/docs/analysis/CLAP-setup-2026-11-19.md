# CLAP-режим для обычного пользователя — что сделано и что осталось проверить

Дата: 2026-11-19 · Ветка: `arena/b9fbca71-sfx1-0` · Коммит: `617c0ce`

## Сначала главное: что здесь НЕ проверено

В песочнице **HuggingFace заблокирован** (`huggingface.co` → нет соединения),
а `laion-clap` качает и веса (`630k-audioset-best.pt`, ~1.9 ГБ), и
токенизатор (`roberta-base`) именно оттуда. Поэтому:

- реальная загрузка модели и качество CLAP-поиска **не проверялись**;
- проверена вся обвязка вокруг модели: состояния, ошибки, офлайн-путь,
  переключение индекса, калибровка (14 тестов без torch).

Первый прогон на машине с интернетом — единственный способ закрыть остаток.

## Что было не так (и почему это важно для «обычных пользователей»)

В `laion_clap/hook.py` (проверено в исходниках пакета 1.1.7):

```python
download_link = 'https://huggingface.co/lukewys/laion_clap/resolve/main/'
...
ckpt = wget.download(download_link + weight_file_name, ...)   # синхронно
```

Старый код вызывал `CLAPEmbedder()` внутри `get_embedder()` **при старте**:

1. бэкенд не отвечает 2–5 минут (скачивание 1.9 ГБ) — UI показывает
   «демо-режим» и пользователь думает, что всё сломано;
2. при обрыве сети — тихий откат в эвристику, без объяснения причины;
3. при повторном запуске с уже скачанными весами — снова проверка, и только
   потом работа;
4. `pip install torch` без `--index-url` тянет ~2.5 ГБ CUDA-сборки на
   машину без GPU;
5. `% совпадения` считался как `cos*100` → у релевантного звука всегда 30–50%,
   «уверенность 90%» не достигалась никогда.

## Что теперь

Состояния рантайма (`backend/app/clap_runtime.py`):

| state | Поведение |
|---|---|
| `disabled` | CLAP не включён — обычный demo-режим, плашки нет |
| `loading` | плашка «Загружаю CLAP — N с · шаг», поиск по словам уже работает |
| `ready` | индекс автоматически пересобирается на CLAP-векторах |
| `failed` | причина + подсказка + кнопка «Повторить» |

Ключевое: **бэкенд отвечает сразу**, потому что модель грузится в фоновом
потоке, а не в `get_embedder()`.

Проверено на живом сервере (`SFX_USE_CLAP=1`, torch отсутствует):

```
$ curl -s localhost:8021/api/clap/status
{"state":"failed","step":"проверяю torch",
 "error":"не установлен torch (No module named 'torch')",
 "hint":"Поставьте ML-зависимости: ./install-ml.sh (Windows: install-ml.bat) ...",
 "active_embedder":"heuristic-demo","ready":false}

$ curl -s -X POST .../api/search -d '{"query":"разбилось стекло"}'
mode: heuristic-demo | найдено: 2 | разбитое стекло
```

То есть отказ CLAP больше не ломает продукт: русский поиск продолжает работать.

## Установка для обычного человека

```bash
./install-ml.sh          # Mac/Linux (Windows: install-ml.bat)
./start-backend-clap.sh
```

Установщик:
- проверяет RAM (<4 ГБ — предупреждает) и свободный диск (<3 ГБ);
- ставит CPU-torch отдельно (`--index-url .../whl/cpu`), чтобы не тянуть CUDA;
- **заранее скачивает веса** в `~/.cache/sfx-clap`, с прогресс-баром;
- флаги: `--no-weights`, `--weights-only`, `--gpu`;
- при сбое печатает три конкретных варианта, а не «error».

`start-backend-clap.sh` сам подхватывает веса из `~/.cache/sfx-clap`.

Офлайн-сценарий (нет интернета на целевой машине):
```bash
# на машине с интернетом
./install-ml.sh --weights-only       # -> ~/.cache/sfx-clap
# перенести папку, затем:
SFX_CLAP_CKPT=~/.cache/sfx-clap/630k-audioset-best.pt \
SFX_CLAP_OFFLINE=1 ./start-backend-clap.sh
```

## Что осталось проверить на машине с интернетом

1. `./install-ml.sh` → доходит ли до «Веса на месте», сколько минут.
2. `./start-backend-clap.sh` → плашка `loading` → `ready`, время загрузки на CPU.
3. Индексация 90 файлов ESC-50 на CLAP: ожидание 2–4 мин, RAM ≤ 4 ГБ.
4. **Главное:** `SFX_QUERIES=scripts/demo_queries_ru.json python scripts/evaluate_recall.py`
   в CLAP-режиме. Русские запросы идут через keywords (CLAP понимает только
   английский) — надо убедиться, что гибрид RRF не уронил метрику.
5. Откалибровать `SFX_CLAP_CALIB=lo,hi` на своих 200 звуках: взять косинус
   лучшего релевантного и лучшего нерелевантного, поставить между ними.
6. Проверить `POST /api/clap/retry` после скачивания весов без перезапуска.

## Известные ограничения

- CLAP понимает **английский** текст. Русские запросы работают за счёт
  словаря `labels_ru` + RRF, а не за счёт модели. Для «понимания» русского
  смысла нужен мультиязычный текстовый энкодер (отдельная задача).
- `device="cuda:0"` поддерживается, но на CPU загрузка и индексация заметно
  медленнее — для библиотек 30–100 тыс. файлов это часы, нужен GPU или
  инкрементальная индексация пачками (уже инкрементальная, но без батчинга
  обучения).
- ChromaDB по-прежнему не подключена: при росте библиотеки до 100 тыс.
  линейный перебор по numpy станет узким местом (сейчас 90 файлов — мгновенно).
