## 2. Главная проблема: метрика R2 недостоверна

### 2.1 В репозитории лежит один датасет, а метрика обещана для другого

`README` (раздел «Метрики») обещает синтетику из `generate_demo_sounds.py`:
8 категорий (`footstep_wood`, `metal_hit`, …) × 5 вариантов = **40 файлов**.

Реально в `data/demo_sfx/` лежит **90 файлов из датасета ESC-50**
(имена вида `1-11687-A-47.wav`, `tags.csv` на 2000 строк с колонками
`fold,target,esc10,src_file`, 50 классов: `dog`, `chainsaw`, `rain`, `glass_breaking`…).

`demo_queries.json` написан **под ESC-50** (`expected: "dog"`… — прогнал, вижу).
Значит одно из двух:

* либо синтетику (40 файлов, под которую написан весь `README`) заменили на ESC-50
  и забыли всё обновить;
* либо метрика `Recall@10 = 1.0` из `data/eval_results.json` получена на *третьей* версии
  данных, которой в репозитории нет.

### 2.2 Фактический замер на том, что лежит в `data/demo_sfx`

```
POST /api/scan?directory=data/demo_sfx     -> {"added": 90}      (18.5 с)
POST /api/search {"query":"собака лает"}   -> results: []        low_confidence: true
POST /api/search {"query":"dog barking"}   -> results: []        low_confidence: true
POST /api/evaluate                         -> recall@5 = 0.0
                                              recall@10 = 0.0
                                              gate_recall@10>=0.5: false
```

`scripts/evaluate_recall.py`, запущенный отдельно, даёт то же: **Recall@5 = 0.0,
Recall@10 = 0.0** на 24 запросах из `demo_queries.json` (24/24 промаха).

### 2.3 Заявленный 1.0 — правда, но для датасета, которого нет

Регенерировал синтетику скриптом в `/tmp/synth_demo` и прогнал тем же `evaluate_recall`:
**Recall@5 = 1.0, Recall@10 = 1.0 на 40 файлах.** То есть код работает — но число в
`README` относится к синтетике, а не к тому набору, что лежит в `data/`.

### 2.4 Почему на ESC-50 нули — не вина модели, а ошибка раскатки данных

Открыл реальный индекс, запись `1-11687-A-47.wav` (класс `airplane`):

```
category: "airplane"          <- из tags.csv (правильно)
tags:     []                  <- ПУСТО
description: "airplane: "     <- склеено с пустыми тегами
```

Каскад причин:

1. `store.scan_folder()` берёт `category/tags` из `tags.csv`, а колонки `tags` в ESC-50-CSV
   **нет** → `row.get("tags","")` → `[]`. Теги теряются молча (`except (OSError, KeyError)`).
2. Синонимический словарь `SYNONYMS` в `embeddings.py` жёстко привязан к 8 синтетическим
   категориям. Для `airplane`/`dog`/`rain` там ничего нет.
3. Короткие имена файлов (`1-11687-A-47`) дают хэши, а не слова — `tokenize` не спасает.
4. Итог: у 90 файлов «лексический след» пустой → эвристический поиск честно возвращает `[]`.

Проверка гипотезы: подменил теги на `category` + её слова (в эксперименте, без коммита) —
**Recall@10 сразу 0.58** даже на слабой демо-эвристике. Остаток промахов — только пробелы
словаря (`dog`, `siren`, `helicopter`, `cat`, `footsteps`). Это доказывает: 0.0 — дефект
подготовки данных, а не архитектуры.

### 2.5 Мелочь, которая добивает доверие

`README` пишет «40 .wav + tags.csv», «категории = имена подпапок», «индексация 40 файлов
~1.5 с». Факт: 90 файлов, одна плоская папка, категория из CSV, 18.5 с (≈0.2 с/файл — на
порядок медленнее обещанного `~0.03 с/файл`).

## 4. Дефекты в коде (по приоритету)

### 4.1 🔴 Потеря пользовательской разметки при повторном скане

Воспроизвёл:

```
annotate(id, ["мой","тег","проверка"])   -> tags = ['мой','тег','проверка']
scan_folder('data/demo_sfx')             -> tags = []
```

`store.scan_folder()`, ветка «reuse» (файл не менялся): если путь есть в `truth` (а для
ESC-50 есть), теги **перезаписываются** из CSV, где они пустые. Для любого пользователя
с `tags.csv` вся ручная разметка испаряется при каждом скане. Это прямо противоречит
`README` («теги целы»). Плюс обратная проблема: `description` строится как
`f"{category}: {', '.join(tags[:8])}"` → в индексе мусор вида `"airplane: "`.

### 4.2 🔴 Фронтенд подменяет результаты случайными числами

`SearchView.tsx` → `fallbackSearch()`: если бэкенд вернул ошибку (например, «Library is
empty — scan a folder first» — 400 при пустом индексе), **любой** запрос уходит в мок,
и пользователь видит «найдено N результатов» со `score = Math.random()*0.2`.
Демонстрация на защите при не просканированном индексе покажет фальшивую релевантность.
То же в `EvaluationMode.tsx` (`fallbackSearch` + `expectedFiles.includes(file.id)`
подмешивает «правильный» файл в скор — метрика на экране физически не может быть плохой).

### 4.3 🟠 Экран «Оценка» не считает Recall@10

`EvaluationMode.tsx` держит 5 захардкоженных запросов с `expectedFiles: ['1']…['5']` —
это id **моков**, а не реальных файлов индекса. Метрика в UI — средняя «звёздочная»
оценка (`avgRating`), а не Recall@5/@10. Слайд 13 обещает «инструмент метрик», слайд 9 —
замер Recall@10 вручную. Бэкенд `/api/evaluate` это умеет и не используется UI.

### 4.4 🟠 Состояние поиска живёт в глобальном store

`searchQuery/searchResults/selectedFile` — глобальные в `useStore`. Переключение
«Каталог → Поиск» показывает прошлые результаты; `pickQuery()` в «Оценке» сбрасывает
`results`, но `selectedFile` остаётся от другого файла. На юзабилити-тесте (HADI-4) это
всплывёт сразу.

### 4.5 🟡 `README` завышает зрелость

* «ChromaDB + FastAPI ✅ D3» — ChromaDB не подключена (только `import chromadb`).
* «40 .wav» — 90 файлов ESC-50.
* «Recall@10 = 1.0» — 0.0 на лежащих данных.
* «категории = имена подпапок» — категории из `tags.csv`.
* `.pyc`-файлы закоммичены (`backend/app/__pycache__/*`, 7 шт.), нет `.gitignore` в корне,
  `.venv/`, `node_modules/`, `frontend/dist/` не игнорируются.

### 4.6 🟡 Поиск по аудио в демо-режиме почти бесполезен

`mfcc_vector()` = 13-мерный усреднённый MFCC, нормированный. Усреднение по времени
стирает атаку и структуру — разные SFX дают близкие векторы. То есть кнопка «найти по
референсу» в demo-режиме работает, но качество не проверено ни одним тестом.

### 4.7 🟡 Мусор в зависимостях

`package.json`: `@supabase/supabase-js`, `recharts`, `framer-motion`, `@dnd-kit/*`,
`date-fns`, `uuid`, `canvas-confetti`, `react-router-dom` — не используются нигде.
`frontend/src/utils/audioAnalysis.ts` (141 строка) — мёртвый код.
`backend/requirements.txt` тянет `librosa` в базовый набор (тяжёлый, нужен только для
`audio_features`), а `scipy` используется только генератором демо-звуков.

## 5. Что сделано хорошо (это стоит защищать)

1. **API-контракт закрыт полностью**, включая двойной режим `/api/scan`
   (sync `?directory=` и async `{"folder"}` + `/api/scan/status`) — фронт менять не надо.
2. **Инкрементальная индексация** по `mtime+size`, стабильные `uuid5(path)`,
   самоочистка от удалённых файлов, миграция по `STORE_SCHEMA`.
3. **Честное «пусто»** вместо 10 результатов с 0 % (`low_confidence`) — редкость для MVP.
4. **Гибридный поиск CLAP + keywords через RRF** — правильное решение конкретно под боль
   «CLAP не понимает русский/сленг» со слайда 17.
5. **Билингвальная эвристика** с толерантностью к склонениям (`_match` по 4-буквенному
   префиксу, EN↔RU-эквиваленты) — под реальные русские запросы.
6. **Zero-shot автотегирование** словарём из 67 меток, `tags.csv` приоритетнее гипотез.
7. **Frontend собирается без ошибок** (`tsc --noEmit` + `vite build`), `allowedHosts: true`,
   относительные URL через Vite-прокси — Electron/прод предусмотрены.
8. `docs/original/` — исходники команды сохранены, история не переписана.

проект можно защищать по презентации без оговорок.
