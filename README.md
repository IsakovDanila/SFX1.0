# SFX Smart Search — MVP v0.1 (слияние готово ✅)

Локальный семантический поиск по библиотеке звуковых эффектов.
**Фронтенд команды** (React + TS + Tailwind + Zustand + WaveSurfer v8)
подключён к **рабочему бэкенду** (FastAPI → CLAP/heuristic → JSON/ChromaDB → Librosa).

## Быстрый старт

**Windows:** двойной клик `install.bat` (один раз), затем `start-backend.bat`
и `start-frontend.bat`. **Mac/Linux:** `./install.sh`, `./start-backend.sh`,
`./start-frontend.sh`. Либо вручную:

```bash
# 1. Бэкенд
pip install -r backend/requirements.txt
python scripts/generate_demo_sounds.py   # 40 .wav + tags.csv (если нет своих)
cd backend && uvicorn app.main:app --port 8000

# 2. Фронтенд (вторым терминалом, из корня)
cd frontend && npm install && npm run dev  # UI: http://localhost:5173
```

В UI: «Каталог» → «Импорт файлов» → «Папка на сервере» → `../data/demo_sfx`
→ «Сканировать». Дальше — поиск словами или референсом, разметка, оценка.

Своя папка звуков: тот же путь, вписать свой путь (на машине бэкенда).

Своя папка подробно:
- демо-звуки необязательны: `data/demo_sfx` можно удалить; каждый скан
  заменяет индекс целиком, а при старте бэкенд сам выкидывает записи
  удалённых файлов (или принудительно `POST /api/index/clear`)
- категории = имена подпапок, теги = слова из имён файлов
- точная разметка: `python scripts/make_tags_template.py "D:\MySFX"` создаст
  `tags.csv` в каждой подпапке — допишите описания в Excel и сканируйте
- поиск билингвальный: русские запросы находят английские имена файлов

## API-контракт (ваш, реализован полностью)

| Метод | Путь | Ответ |
|---|---|---|
| `POST` | `/api/scan?directory=` | `{"status":"ok","added":N}` (синхронно) |
| `POST` | `/api/scan {"folder"}` | `{"accepted":true}` + прогресс в `/api/scan/status` |
| `POST` | `/api/index/clear` | очистить индекс (напр. после удаления демо-папки) |
| `POST` | `/api/search {"query","n_results"}` | `{results:[{id,score,file:{...}}]}` |
| `POST` | `/api/search/audio` (multipart, опц. `?query=`) | `{results:[...], mode?}` |
| `GET` | `/api/files` | `{files:[...], count}` |
| `PUT` | `/api/files/{id}/tags` | `{"status":"ok"}` |
| `PUT` | `/api/files/{id}/description` | `{"status":"ok"}` |
| `GET` | `/api/files/{id}/audio` | стрим для WaveSurfer |
| `GET` | `/api/health` | индикатор в футере |
| `POST` | `/api/evaluate` | Recall@5/Recall@10 (скрипт/интеграция) |

`file`: `{id, filename, duration, sample_rate, channels, category, tags,
description, spectral_features:{pitch(низкий/средний/высокий),
energy(low/medium/high), has_noise, has_reverb}}`.

## Русские теги и русский поиск

Теги **ставятся на русском**: интерфейс и звукорежиссёры говорят по-русски,
а ключи датасета приходят по-английски (`glass_breaking`, `dog`). Словарь
`backend/app/labels_ru.py` даёт каждой категории русское название и синонимы
профессионального сленга — при сканировании они пишутся в `tags`:

```
1-20133-A-39.wav   category: glass_breaking / category_ru: «разбитое стекло»
  tags: разбитое стекло, стекло, звон стекла, осколки, разбивание, бьётся стекло
```

Поэтому работают живые запросы: «разбилось стекло», «тиканье часов», «гроза»,
«апчхи», «бибикает», «пылесосит ковёр», «кукареку», «треск костра».
Покрыты 50 классов ESC-50 + 8 синтетических + алиасы чужих библиотек
(`glassbreak`, `ui_click`, `wind_loop`, …). Неизвестный класс не ломает поиск:
теги строятся из имени папки/файла, а `keywords`-поиск остаётся рабочим.

- Теги из `tags.csv` имеют приоритет, но **не затирают** ручную разметку:
  добавленные через «Разметку» теги переживают повторный скан.
- В UI категория показывается по-русски (`category_ru`), ключ датасета
  остаётся в `categoryKey` — группировка не ломается.
- Свой словарь: добавьте запись в `RU_LABELS` (`key -> {"ru", "tags"}`).

### А если `tags.csv` нет?

Тогда работает цепочка: **имя папки → имя файла → словарь `labels_ru`**.
CSV необязателен, но нужна хотя бы одна зацепка в именах:

| Как названы файлы | Что будет в тегах | Поиск по словам |
|---|---|---|
| подпапка `glass_breaking/`, мусорное имя файла | русские теги из словаря по папке | ✅ работает |
| подпапка `Glass_Breaking/` (большая буква) | то же — регистр приводится | ✅ работает |
| `разбитое_стекло_01.wav` в плоской папке | слова из имени + русские метки | ✅ работает |
| `glass_breaking_01.wav` в плоской папке | англ. слова + русские метки | ✅ работает |
| `1-20133-A-39.wav`, папка `d_esc50/` | теги только из имени папки | ❌ ничего |

Русский запрос переводится в категорию **до** сравнения с тегами
(`expand_query`): даже если в индексе только английское имя файла,
«разбилось стекло» найдёт `glass_breaking_01.wav`.

Единственный честный тупик — мусорные имена без CSV (как сами файлы ESC-50:
`1-20133-A-39.wav`). Определить звук по звучанию в demo-режиме нельзя: 1-NN по
MFCC-признакам угадывает класс лишь в 38% случаев. Для таких библиотек нужен
CLAP-режим (`SFX_USE_CLAP=1`) или разметка. UI предупредит об этом после скана:
«У N из M файлов нет ни тегов, ни осмысленного имени».

## Поиск по референсу и по тексту — раздельно

Два режима не смешиваются. Загружен референсный `.wav` — поиск идёт только
по звуку; текст в поле игнорируется (интерфейс об этом предупреждает).

Так сделано по замеру, а не из осторожности: при складывании с весами
`SFX_W_AUDIO=1.0` / `SFX_W_CLAPTEXT=0.8` неточное описание поднимало
неверный файл выше правильного —

```
только референс:      A_correct 99%, A_second 91%, B_wrong  5%
референс + «dog»:     B_wrong   54%, A_correct 56%, A_second 97%   <- порядок сломан
```

Проценты в выдаче всегда идут по убыванию и согласованы с порядком списка.

Про 5-секундные файлы: окно CLAP — 480 000 сэмплов @ 48 кГц (10 с).
Файл ровно 5 с даёт `n_repeat = 2` — сигнал проигрывается дважды, добивки
нулями нет. Это лучший случай: у файла 3.2 с уже 32% окна занимают нули,
и вектор «размазывается».

## Удаление индекса при остановке

`index.json` — кэш векторов, привязанный к текущему режиму (13-d эвристика
против 512-d CLAP). При остановке бэкенда он удаляется: иначе после смены
режима поиск падает на `cosine(13-d, 512-d)`.

Отключить: `SFX_INDEX_KEEP=1`.

## Режимы эмбеддера

- **Demo (по умолчанию):** текст — синонимы+теги (EN+RU), сходство аудио —
  косинус по MFCC. В футере «API: демо-режим» только если бэкенд недоступен;
  при запущенном бэкенде — «API: подключён».
- **Full CLAP (рекомендуется для реальных библиотек):** `install-ml.bat`
  (CPU torch ~200 МБ + laion-clap), затем `start-backend-clap.bat`.
  Установщик проверяет RAM/диск, ставит CPU-torch отдельно (чтобы pip не
  притащил 2.5 ГБ CUDA) и **заранее скачивает веса** — чтобы первый запуск
  не «висел». Флаги: `--no-weights`, `--weights-only`, `--gpu`.
  Первый запуск докачивает веса `630k-audioset-best.pt` (~1.9 ГБ) и
  токенизатор RoBERTa. Требования: ~4 ГБ свободной RAM, ~3 ГБ на диске
  (torch + веса). Индексация на CPU: ~1–2 с/файл (96 файлов ≈ 2–4 мин
  один раз, с прогресс-баром); повторные сканы инкрементальные.
  Поиск гибридный (CLAP + keywords через RRF): английская семантика +
  русские теги/синонимы. CLAP понимает английский — для лучшего качества
  запросы на английском или теги на русском. Тот же API и скрипты оценки.

### CLAP-режим для обычного пользователя

Модель (~1.9 ГБ) **грузится в фоне**: сервер отвечает сразу, а не через
несколько минут, и UI показывает честную плашку вместо молчаливого
«демо-режима».

| Состояние | Что видит пользователь |
|---|---|
| `loading` | «Загружаю CLAP — N с», шаг загрузки; поиск по словам уже работает |
| `ready` | зелёная отметка «CLAP загружен за N с · cpu», затем гаснет |
| `failed` | причина + что сделать + кнопка «Повторить» |
| `disabled` | ничего (обычный demo-режим) |

Пока модель грузится и если она не загрузилась, поиск **не падает**:
работают русские теги и `keywords`-поиск. Когда CLAP готов, индекс
автоматически пересобирается (у CLAP-векторов другая размерность).

Офлайн-установка (машина без интернета):
```bash
# на машине с интернетом
./install-ml.sh --weights-only     # веса -> ~/.cache/sfx-clap
# перенести папку ~/.cache/sfx-clap на целевую машину, затем:
SFX_CLAP_CKPT=~/.cache/sfx-clap/630k-audioset-best.pt SFX_CLAP_OFFLINE=1 ./start-backend-clap.sh
```
`start-backend-clap.sh` подхватывает веса из `~/.cache/sfx-clap`
автоматически, если они там есть.

### Настройки в файле вместо терминала

Скопируйте `.env.example` в `.env` и заполните один раз:

```bash
cp .env.example .env        # Windows: copy .env.example .env
```

```ini
HF_TOKEN=hf_ваш_токен      # ускоряет скачивание весов CLAP
SFX_USE_CLAP=1
SFX_CLAP_MIN_COS=0.18
```

Бэкенд читает `.env` при старте (сам, без `python-dotenv`). Файл **добавлен в
`.gitignore`** и в репозиторий не попадает; приоритет у переменных ОС — если
задать `HF_TOKEN` в системе, она перебьёт `.env`. Шаблон — `.env.example`.

Переменные окружения:

| Переменная | Смысл |
|---|---|
| `SFX_USE_CLAP=1` | включить CLAP-режим |
| `SFX_CLAP_CKPT=/path.pt` | локальный файл весов (без скачивания) |
| `SFX_CLAP_OFFLINE=1` | не ходить в сеть, только локальные веса |
| `SFX_CLAP_MODEL_ID` | `0` = 630k-best, `1` = 630k-audioset-best |
| `SFX_CLAP_DEVICE` | `cpu` / `cuda:0` (по умолчанию авто) |
| `SFX_CLAP_CALIB=lo,hi` | калибровка «% совпадения» под свою библиотеку |

Статус в API: `GET /api/clap/status` (для плашки),
`POST /api/clap/retry` (повторить после скачивания весов),
блок `clap` в `GET /api/health`.

> **Честно про `% совпадения`.** CLAP отдаёт косинус в узком диапазоне
> (~0.3–0.6 у релевантного), поэтому `cos*100` показывал бы 30–50% у всего.
> Уверенность переводится логистической кривой (`SFX_CLAP_CALIB`), а не
> берётся сырой. Значения по умолчанию подобраны, но не откалиброваны на
> реальной библиотеке — на 200 своих звуках их стоит уточнить.
- **Авто-тегирование (только CLAP-режим):** при скане каждый файл сравнивается
  со словарём из ~60 меток (речь/мемы, музыка, эффекты — см.
  `backend/app/autotag.py`) и топ-совпадения пишутся в `auto_tags` с оценками,
  а также добавляются в обычные теги (русская метка + короткая английская),
  чтобы их сразу находил поиск. `tags.csv` по-прежнему главнее: где он есть,
  авто-теги только показываются в «Разметке» как гипотезы. Честные границы:
  речь размечается по звучанию (мужская/женская, крик, смех), а не по смыслу
  слов — расшифровка содержания мемных фраз требует ASR (Whisper), это
  следующий шаг. Настройка: `SFX_AUTOTAG_TOPK` (по умолчанию 3),
  `SFX_AUTOTAG_THRESHOLD` (по умолчанию 0.12), свой словарь —
  `SFX_LABELS_PATH` (JSON вида `[{"en": "...", "ru": "...", "group": "..."}]`).
